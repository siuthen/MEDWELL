# 생산계획 운영

## 현재 동작

- 직접 등록은 계획월과 여러 행의 제품 선택(품목코드/품목명 자동완성)·계획수량을 받는다. 날짜는 월 1일이며 `createDirectProductionPlans`가 전체 행을 한 번에 검증·저장한다. 코드 또는 유일 정확 품명/수량 2열을 붙여넣을 수 있다. 자유 텍스트는 저장하지 않는다.
- 파일 업로드는 기존 XLSX/UTF-8 CSV 표와 병합형 보고서를 지원한다. 표시 시트 `26.10-11월계획`은 2026-10~2026-11이다. B열 월별 순번은 날짜로 해석하지 않는다.
- 코드의 trim/대문자 정확 일치가 우선이다. 실패하거나 코드가 없으면 시장 접두사·구두점·공백·괄호·용량을 정규화한 품명으로 추천한다. 유일 후보만 자동 선택하고 모호한 후보는 사용자가 고른다.
- `직접 입력(BOM 수기)`는 활성 부자재를 참조하는 이름/용량/단위/BOM을 이 계획에만 저장한다. 제품 마스터를 만들지 않는다. 일반/수기 행은 같은 배치에 포함할 수 있다.
- 미승인 제품은 차단한다. `usageEra=pre_2023_only`만 기존 승인 예외를 유지한다. 빈 BOM, 미등록 자재, 중복 BOM 자재, 유한 양수가 아닌 수량은 차단한다.

## 창고 배정과 스냅샷

포함된 유효 행의 공통 자재 필요량을 먼저 합산한다. 단일 창고로 충족하면 현재고가 더 많은 창고를 사용한다. 불충족이면 양수 현재고가 많은 창고부터 나누어 쓰고, 부족분은 원래 현재고가 많았던 창고에 추가 배정한다. 동률은 김포가 우선이다. 부족한 재고는 경고하며 확정할 수 있다.

각 BOM 스냅샷은 코드·이름·단위·단위소요량·총소요량·`warehouseAllocations`를 저장한다. 재고는 활성 계획의 저장된 배정량을 뺀다. 취소/교체는 현재 BOM을 사용하지 않고 이 배정을 정확히 복원한다. 과거 단일 창고 레코드는 기존 `warehouse`와 `lines.qty`를 그대로 사용한다.

## 파일 배치

파일명 대신 `periodKey`로 활성 배치를 찾는다. `replaceProductionPlanBatch`는 전체 재검증 후 이전 배치/행을 replaced로 보존하고 현재 BOM으로 새 스냅샷을 만든다. 이전 차감 복원과 새 차감은 한 CAS 저장으로 반영한다. 같은 기간 활성 배치는 하나이며 revision이 증가한다. 직접 등록/과거 batchId 없는 기록은 교체하지 않는다. 마감된 기간은 교체/취소하지 않는다.

`version` 또는 `expectedVersion`, `requestId`, `expectedBatchId`로 동시성/재시도를 제어한다. 성공 시 version과 감사로그가 각각 한 번만 증가한다. 실패 시 DB에 일부 결과나 migration을 저장하지 않는다.

## 공통 XLSX 생성기

직접 등록 미리보기, 업로드 자동작성, 저장 배치 다운로드는 `buildProductionXlsx`와 동일한 canonical `data/production-report-layout.json`을 사용한다. 이 레이아웃은 첨부 원본에서 운영 계획값과 개인 경로 메타데이터를 제거한 시트/서식 정보다. 원본 XLSX 자체는 커밋하지 않는다. 업로드한 일반 XLSX는 canonical 양식을 대체하지 않는다. 템플릿/필수 구성요소가 없거나 훼손되면 오류로 중단하며 빈 표준 워크북으로 fallback하지 않는다.

- 메인 시트 `26.10-11월계획`의 A1:AA130 최소 영역과 기존 행 1~130을 유지한다. 기존 행의 값만 비우며 행높이·열너비·셀 스타일·테두리·채우기·폰트·제목·헤더·인쇄설정·시트 순서·숨김 상태를 보존한다.
- 데이터 영역의 A/B/C/D/J 제품 병합을 새 블록에 맞게 구성하고, 제목/헤더와 다른 양식 병합은 유지한다. B는 공란이며 제품 블록 높이로 병합한다. 공간을 초과할 때만 행 스타일을 복제해 추가하며 하단 서명 영역 병합은 데이터 뒤로 보존한다.
- A=월, C=정식/수기 이름, D=용량, J=계획수량, P=자재명, Q=두 창고 총현재고를 입력한다. E:I/K:O/R:Z와 사용하지 않은 데이터 행 값은 공란이다. 제품 순서는 입력 순서다.
- J/Q는 number와 `#,##0.###`이며 날짜 형식을 상속하지 않는다. Q 메모는 자재코드·단위소요량·총필요량·통합 현재고만 포함한다. 창고별 수량과 자동배정은 표시하지 않는다.
- workbook.active는 메인 시트다. 틀 고정의 xSplit/ySplit/state를 유지하고 view/pane의 topLeftCell 및 선택 activeCell/sqref는 A1로 정상화한다.
- `BOM자동계산`은 기간·제품코드/명·계획수량·자재코드/명·단위소요량·총필요량·통합 현재고·계획 후 통합재고·상태를 BOM 한 라인당 한 행으로 기록한다. 창고/배정 열은 없다. 메인 P/Q 라인 수와 일치하며 수기 완제품 코드는 공란이다.
- 직접 등록은 클릭 순간 실제 검색문자열·선택된 productCode·수량·계획월을 읽고 제품 선택 및 BOM을 동기적으로 재검증한다. 업로드도 최신 행 참조로 재검증한다. 미등록·미승인·빈 BOM·수량 오류가 있으면 버튼을 비활성화하고 이벤트가 호출돼도 파일 생성을 차단한다. 제외된 업로드 행은 파일에도 포함하지 않는다.
- 저장된 배치 다운로드는 `snapshot:true`로 저장 당시 BOM을 검증·출력한다. 현재 BOM으로 과거 차감량을 바꾸지 않는다. CSV 자동작성은 기존처럼 비활성화한다.
- 다운로드는 브라우저 내 파일 생성만 수행하며 API state를 저장하거나 전표를 만들지 않는다.

## 삭제와 내부 이력

변경 이력 메뉴/페이지/대시보드 섹션은 제공하지 않지만 감사로그는 서버에 유지한다. 재고 화면에는 usageEra 표시가 없으며 제품·BOM의 구분과 승인 예외는 유지한다.

발주/입고 삭제는 `deleteOrder`/`deleteReceipt` 단일 action과 `expectedVersion`/`requestId`를 사용한다. 연결 입고가 남은 발주는 삭제할 수 없다. 입고 삭제는 paid+free 증가분을 역반영하고 연결 발주 상태를 다시 계산한다. 음수 예상재고는 사용자 확인(`allowNegative:true`)이 필요하다. 마감 잠금을 유지하며 각 삭제당 감사로그 1건을 남긴다. 삭제 레코드는 내부 soft-delete로 보존한다.

## 검증

`tests/*.test.mjs`는 fixture/mock DB만 사용한다. 외부 실제 첨부를 다시 여는 테스트는 `MEDWELL_REPORT_FIXTURE_PATH`로 원본을 읽기 전용 전달한다. Python openpyxl이 필요하다. 실제 원본은 커밋하지 않는다. 전체 테스트/타입검사/빌드 및 배포 중 운영 전표 생성·수정·삭제를 하지 않는다.

## 발주 완료 전환과 입고 자동 등록

`orderEdit`는 historical/orders 모두를 수정하며, 저장 전 원본 상태와 계산 상태가 모두 완료가 아니고 저장값이 `입고완료`일 때만 `autoReceipt`를 요구한다. 기존 완료 레코드는 소급 입고를 만들지 않는다. UI는 입고일(오늘), 창고(현재고 큰 창고·동률 김포), 유상 잔량, 무상 추가수량을 보여준다. legacy 잔량은 전체 qty, 신규 잔량은 주문 qty에서 연결 입고의 유상수량 합계를 뺀 값이다.

서버는 원본 발주와 active receipt를 재조회해 전체 검증 후 발주/자동 입고/감사로그를 메모리에서 완성하고 단일 version CAS로 저장한다. `expectedVersion`/`requestId` 및 살아 있는 `sourceOrderId` 자동 입고 검사로 중복을 막는다. 실패 시 seed/migration이나 부분 결과를 저장하지 않는다.

자동 입고는 기존 `date/paid/free/orderId` API 필드와 함께 `receiptDate/quantity/extraQuantity/sourceOrderId/source=order_completion/autoGenerated/inventoryApplied`를 저장한다. active material과 정확히 일치하지 않는 legacy 코드는 `inventoryApplied=false`로 목록에만 남기며 재고 증가·삭제 역반영 모두 생략한다. 새 자재나 재고 전표를 임의 생성하지 않는다. 기존 입고의 플래그 부재는 종전처럼 재고를 반영한다.

자동 입고가 남은 발주의 완료 상태 역전은 금지한다. 자동 입고는 삭제 후 발주에서 재등록하며, 삭제는 저장된 증가분만 되돌리고 historical/orders 상태를 남아 있는 유상 입고로 다시 계산한다(남은 입고 없음=대기, 일부 잔존=부분입고). 자동 입고의 수정 연필은 비활성화하며 서버도 직접 수정을 차단해 원본 연결과 재고 적용 플래그를 보존한다. 일반 입고 등록/수정/삭제는 기존 동작을 유지한다.

## 자동완성과 통합 재고 UI

검색은 활성 제품에서 코드 완전일치 → 코드 prefix → 코드 포함 → 정규화 품명 prefix → 품명 포함 순으로 최대 10개를 제공한다. 공백/특수문자/괄호를 무시하며 시장 접두사는 후보의 정식 제품명에서 유지한다. 클릭과 ↑/↓/Enter/Escape를 지원하고 combobox/listbox/option ARIA를 제공한다. 후보 목록은 입력 아래 문서 흐름에 있어 모바일에서도 다른 행을 가리지 않는다.

선택 뒤 텍스트를 바꾸면 productCode를 지운다. blur/붙여넣기는 코드 정확일치 또는 정규화 품명 유일 정확일치만 자동 선택한다. 시장별 동명이 여러 개이면 임의 확정하지 않는다. 확정/다운로드 전 현재 입력과 선택 코드를 다시 비교한다.

직접/업로드 미리보기는 자재코드별 필요량을 합산한 `부자재 통합 재고`만 보여준다. 통합 현재고는 김포+오류, 계획 후 재고는 교체 시 기존 스냅샷 복원을 포함해 계산한다. 음수는 오류가 아니며 중립 `발주 필요` 표시만 붙이고 다운로드/확정/교체를 허용한다. XLSX에도 음수를 number로 보존한다. 내부 warehouseAllocations·BOM 스냅샷과 차감/취소/교체 로직은 변경하지 않는다.
