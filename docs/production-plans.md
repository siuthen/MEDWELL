# 생산계획

생산계획은 `productions`에 추가되며 기존 API와 과거 기록은 유지한다. 기존 입고·재고 계산은 변경하지 않는다. 새 계획은 `kind: productionPlan`, `plannedQty`, `fileName`, `source`와 확정 당시의 `version` 및 자재 차감 `lines`를 저장한다. `normal`에는 계획수량, `retained`에는 0을 함께 저장하여 기존 소비자와 호환한다.

업로드는 재고 업로드의 15MB/압축 해제 제한을 공유하며 최대 5,000행을 허용한다. 완제품 코드와 계획수량 헤더는 필수이며, 계획일은 화면 기본 계획일(초기값: 한국 시간 오늘), 창고는 화면 기본 차감 창고를 적용한다. 인식할 수 없는 비어 있지 않은 시트나 오류 행이 있으면 확정을 막는다. 음수 예상재고는 경고하되 허용한다.

`bulkProductionPlan`은 모든 행을 서버에서 재검증한 다음 한 번의 상태 CAS로 저장한다. 승인된 BOM 또는 `pre_2023_only`만 허용한다. 업로드당 감사로그 한 건에 파일명·계획 건수·차감 라인 수를 기록한다. 기존 version과 requestId 처리로 동시 저장 충돌과 중복 차감을 방지한다.

재고는 미취소 기록의 저장된 차감 라인으로 계산한다. BOM 마스터를 나중에 수정해도 이미 확정한 계획은 달라지지 않는다. 같은 제품의 계획수량 수정은 최초 스냅샷을 비례 조정하며 제품 변경 시 현재 제품 BOM을 새로 검증·저장한다. 취소는 기록을 보존하고 차감만 해제한다. 과거 기록에는 자동으로 새 필드를 쓰지 않는다.

테스트는 로컬 메모리 상태와 모의 DB만 사용한다. `tests/production-plan-api.test.mjs`는 실제 POST 함수를 모의 DB에 연결해 전체 실패, version 충돌, 동시 CAS, 중복 요청, 서버 BOM 검증을 검사한다. 운영 API로 테스트 전표를 만들지 않는다. 전체 테스트는 `tests/*.test.mjs` 각각을 `node`로 실행하고 타입 검사는 `tsc --noEmit`, 배포 빌드는 `npm run build`로 검사한다.


## 병합형 보고서 미리보기

일반 코드·수량 표를 우선 인식한다. 일반 헤더가 없는 표시 XLSX 시트에서만 제품생산계획수량 제목, J열 제품 계획 보고란·계획수량, B/C/D열 순번·품명·용량을 함께 확인한다. B열 월별 순번과 C 품명 또는 M 제품코드가 있는 행만 제품 행으로 추출한다. J열은 숫자 뒤 개·박스·EA 단위를 허용하고, 박스 내용물 수를 곱하지 않는다. 원본 파일은 코드나 테스트에 포함하지 않는다.

제품 추천은 정규화된 이름과 용량(세트 구성 수 포함)이 일치하는 활성 제품이 하나일 때만 적용한다. 접두사·괄호 설명·공백·플러스 표기를 정규화하되 부분 이름 검색, 유사 철자, 용량 추측으로 선택하지 않는다. 후보가 여러 개이거나 없는 경우 사용자가 활성 제품을 선택하거나 해당 행을 제외해야 한다.

포함 체크는 업로드 화면의 선택 상태이며 운영 데이터에 저장하지 않는다. 제외된 행은 오류 집계·자재 합계·확정 payload 모두에서 빠진다. 기본 날짜·창고 변경과 제품 선택은 미리보기를 즉시 다시 계산한다. 서버 bulkProductionPlan 검증, 저장 구조, 원자 처리, 취소·입고 로직은 그대로 유지한다.

## 파일 배치 교체

새 파일 업로드는 `replaceProductionPlanBatch`로 저장한다. periodStart/periodEnd/periodKey가 같은 active 배치만 교체하며, 파일명으로 연결하지 않는다. 이전 배치는 replaced, 새 배치는 active로 보존하고 replaces/replacedBy로 연결한다. revision은 같은 기간의 취소·교체 이력을 포함한 최댓값에서 1 증가한다. batchId가 없는 과거 기록과 직접 등록은 자동 연결하거나 수정하지 않는다. 구 bulkProductionPlan API는 하위 호환을 위해 유지한다.

서버가 새 계획 전체와 현재 제품 BOM을 검증한 뒤 기존 배치의 저장된 차감 라인을 비활성화하고 새 스냅샷·배치·단일 감사로그를 조립한다. 기존 DB의 version 조건부 UPDATE 한 번으로 전체 상태를 저장한다. requestId와 expectedBatchId를 함께 검사한다. 교체 중 검증·동시 저장·용량 검사 실패 시 DB에 부분 저장하지 않는다. 배치 행의 개별 수정·취소는 막고 active 배치 전체 취소만 허용한다.

병합형 `26.10-11월계획`은 2026-10~2026-11을 뜻한다. 순번의 앞 숫자는 무시하고 월만 읽어 매월 1일을 사용한다. 월별 계획일은 재고 기초일보다 앞설 수 있으므로 파일 배치에만 날짜 하한 예외를 적용하며 마감월 보호는 유지한다. 일반 파일은 포함된 명시 날짜의 최소~최대 월을 추천하고, 추출 불가 시 사용자가 시작·종료월을 선택해야 한다. 모든 포함 행 날짜는 선택 기간 안에 있어야 한다.

## XLSX 자동작성 및 배치 다운로드

자동작성은 브라우저에서 원본 ZIP의 복사본을 생성한다. API를 호출하거나 state를 저장하지 않는다. 일반 CSV는 자동작성 대상에서 제외한다. 원본 XLSX의 기존 시트·숨김 상태·병합·열너비·행높이·스타일·인쇄 설정을 유지하고, 지정 셀의 기존 수식도 덮어쓰지 않는다. 수정하지 않은 ZIP 엔트리의 내용은 그대로 보존한다. 매칭 결과와 BOM자동계산 상세 시트를 추가하며 Excel에서 수식이 재계산되도록 fullCalcOnLoad를 설정한다.

보고서 M열의 활성 제품코드를 최우선으로 사용하고, 코드가 없을 때만 기존 보수적인 품명·용량 매칭을 적용한다. J열이 비어 있으면 같은 active 배치의 해당 제품·월·창고 수량을 보완한다. 같은 제품이 여러 달에 있을 때는 월·창고를 우선 일치시키고, 동일 키의 입력 행이 여러 개라 수량 중복 대입 위험이 있으면 자동 보완하지 않는다. 수량을 확정할 수 없는 행은 오류로 남으며 파일 다운로드는 가능하지만 서버 확정은 차단한다.

C/D/J/M을 정리하고 제품 시작 행 및 다음 제품 전까지의 빈 P/Q/R 셀을 사용한다. 수식·병합 영역의 비시작 셀을 덮어쓰지 않는다. 공간이 부족하면 다른 제품 영역이나 행 구조를 바꾸지 않고 모든 BOM을 BOM자동계산 시트에 기록한다. P에 자재코드·자재명·단위소요량·총필요량, Q에 현재고, R에 max(0, 해당 BOM 필요량 − 현재고)를 표시한다. 상세 시트 예상재고는 같은 자재·창고의 파일 전체 필요량을 기준으로 계산하며 재고 조회 시점의 값이다.

배치 이력의 표준 XLSX는 저장된 제품명·BOM 라인·버전·수량으로 생성한다. replaced/cancelled도 다운로드 가능하며 현재 마스터 BOM으로 과거 라인을 재계산하지 않는다. 다운로드 당시 현재고를 참고 정보로 표시하므로 과거 확정 시점의 재고 스냅샷을 뜻하지 않는다.

자동작성의 예상재고는 같은 기간 활성 배치가 있으면 그 저장된 차감량을 복원한 뒤 새 필요량을 반영한다. 활성 배치 자체를 표준 파일로 내릴 때도 현재고에 이미 반영된 수량을 중복 차감하지 않는다. 교체·취소 이력의 예상재고는 현재고를 기준으로 해당 스냅샷을 적용했을 때의 참고값이다.
